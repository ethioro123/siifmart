# Picking audit — 24 October 2026

Code review covers queue selection, route/product lookup, collection, scanner verification, quantities, shortages, completion and packing handoff. This is not an authenticated end-to-end staging certification.

## Fixed

- Cancelled PICK jobs are excluded from the active queue.
- Product lookup prefers the manifest product record, then its source bin, within the job site, before a SKU fallback.
- Resumed scanner picking is bounded by remaining quantity; the parent handler also validates before persistence.
- Confirmed scanner shortages resolve as Short and are included in resolved progress, rather than leaving the same line active.
- Each new scanner line resets location/item verification and shortage mode.
- Unit selection is limited to the product's declared unit. Removed silent inference that an entered measure equal to the case count means full cases.
- Remaining fills outstanding quantity in the displayed measure. Decimal input is accepted explicitly.
- Mobile quantity inputs can shrink; scanner instructions can scroll on short screens.
- Manual collection rejects over-picking rather than silently clipping the entered count.
- Manual line lookup no longer falls back to the first matching SKU when duplicate SKU lines exist.
- Failed completion leaves the picking interface open.

## Outstanding business-logic risks

1. **Completion is not atomic.** `useJobCompletion` saves the completed PICK, then creates PACK/updates the parent, then deducts inventory through separate calls. An interruption can leave a completed PICK without the stock deduction or handoff. A trusted, idempotent transaction should perform these together, accounting for the separate storefront reservation workflow. This audit did not change database completion.
2. **Transfer stock deduction chooses the first source-site SKU.** The completion hook can override the manifest product ID with another lot/bin sharing the SKU. UI lookup fixes do not repair this persistence path. A server transaction should verify source lot, bin, capacity and available stock before deduction.
3. **Manual collection bypasses bay scans.** The collect view can mark quantities through manual controls and its barcode field without the scanner's location-proof sequence. Whether to allow this as a supervisor exception needs an explicit operational policy enforced on the server.
4. **Zero-quantity shortages have no dedicated resolution action.** Positive partial shortages are now supported correctly; completely missing stock still needs a reasoned, audited zero-pick action and an explicit no-pack outcome when all lines are short.
5. **Completion error text is too specific.** A failure after completion may be reported as failed PACK creation even if the failure was parent update or inventory deduction. Recovery should be driven by persisted server stage, rather than guessing from the caught error.

## Verification

Focused quantity/progress/product-resolution and barcode tests cover the changed logic. TypeScript, file-size checks and full-suite results are reported with the implementation. Actual hardware scanning and authenticated staging picking remain unverified.
