# Picking audit — 24 October 2026

Code review covers queue selection, route/product lookup, collection, scanner verification, quantities, shortages, completion and packing handoff. This is not an authenticated end-to-end staging certification.

## Fixed

- Cancelled PICK jobs are excluded from the active queue.
- Product lookup prefers the manifest product record, then its source bin, within the job site, before a SKU fallback.
- Resumed scanner picking is bounded by remaining quantity; the parent handler also validates before persistence.
- Confirmed scanner shortages resolve as Short and are included in resolved progress, rather than leaving the same line active.
- Each new scanner line resets location/item verification and shortage mode.
- Unit selection is limited to the product's declared unit. Removed silent inference that an entered measure equal to the case count means full cases.
- Remaining fills outstanding quantity in the displayed measure. Decimal input is accepted explicitly.
- Mobile quantity inputs can shrink; scanner instructions can scroll on short screens.
- Manual collection rejects over-picking rather than silently clipping the entered count.
- Manual line lookup no longer falls back to the first matching SKU when duplicate SKU lines exist.
- Failed completion leaves the picking interface open.

## Remaining audit findings resolved

- `record_pick_line` persists a protected, audited scan receipt after validating the assigned employee, site/country, exact product, source-bin label checksum/site prefix, physical quantity and shortage reason. Direct REST count edits and completion cannot manufacture this proof.
- `complete_pick_job` locks the job and exact lots, verifies every receipt, deducts stock, records movements, completes assignments, updates the parent and creates one unassigned PACK in one transaction. A persisted completion record makes retries return the same result without deducting stock again.
- Lot number, expiry and bin are captured at scanning and rechecked before deduction. Expired/held stock cannot be picked. Reserved storefront stock remains protected; online completion releases and deducts the matching reservations atomically, preserving full-order shortage rules.
- Manual quantity editing was removed from collection. All workers use the same bay/product/physical-count flow. Each modal has one bottom primary action.
- After scanning the source bay, workers can choose **No stock in this bay** and enter a required reason. Zero and partial shortages are audited; packing contains only positive picked quantities. An all-short transfer is cancelled; an all-short sale returns to Pending fulfillment without changing payment or financial status. No empty PACK is created.
- Completion errors report that server confirmation failed, or the observed rejection, without claiming a particular follow-up failed. Success appears only after the atomic RPC confirms the result. The completion control is locked while saving.
