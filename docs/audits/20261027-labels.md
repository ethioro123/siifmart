# Labels tab audit — 27 October 2026

## Fixed

- Product matching is facility scoped, trims input, prefers exact SKU/barcode/ID/alias matches, and requires a unique SKU for name searches. Ambiguous and unknown product searches cannot generate arbitrary product labels.
- Copy counts are bounded to 1–1000 whole labels in the main controls and preview callback, with validation repeated before generation.
- One print-job hook locks overlapping generation/print requests, displays generation and handoff failures, and reports print-dialog handoff rather than claiming physical output.
- Preview stays open after Print so a blocked handoff or error can be corrected. Preview receives actual printing state and cannot launch repeated jobs while busy.
- Facility changes remount the label workspace, resetting product/copy/preview/bin selection. The tab uses the existing facility zone context rather than a separate asynchronous request that could display stale zones.
- Bay labels use only configured local zones, parse standard Zone A names into a valid zone letter, constrain aisle/bay counts to the barcode format and reject invalid encoded payloads. No synthetic default zones are offered when configuration is absent.
- Mobile mode/format controls have 44px touch targets; product summaries wrap long names, identifiers and categories. Removed an unverified 1:1 preview claim.

## Verification and limits

Focused tests cover ambiguous names, exact identifiers, facility boundaries, invalid copy counts, duplicate print requests, failed generation, blocked handoff and accurate notifications. TypeScript, file-size and full-suite results are reported with the change.

No database changes were made. This pass does not certify physical printer output, browser print scaling, configured physical bay accuracy or live RLS. Layout dimensions come from existing site settings. The separate record_pick_line HTTP 400 report remains outstanding and is not resolved by these label fixes.
