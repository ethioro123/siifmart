# Putaway audit — 24 October 2026

## Fixed

- A saved placement is reflected locally before job/PO completion is attempted. If completion fails, the worker is told the stock was saved and can retry completion without placing it again.
- Recorded Short lines count as resolved in the job review, allowing completion retry rather than forcing another stock scan.
- Duplicate/missing-line scans reject instead of returning an apparent success.
- Decimal physical quantities are preserved; parsing no longer truncates them to whole units. Numeric controls explicitly allow decimals.
- Every new item resets the scanner to LOCATION and clears the previous SKU/overflow mode. Product matching occurs before entering the count step. Physical count starts blank.
- Item matching retains meaningful SKU punctuation rather than merging different identifiers. Source product lookup prefers the manifest product/lot within the facility.
- Removed the active page-load auto-repair invocation that created products from cross-site/global templates. Missing catalog records now require the receiving repair workflow; opening putaway does not create products or copy pricing.
- Critical priority is no longer lost through a falsy-zero fallback. Date sorting uses createdAt rather than attempting to parse UUIDs as dates.
- Quantity quick actions use 44px targets; item names wrap; success feedback blocks repeat submissions. Scanner errors preserve the observed server rejection rather than labelling every failure an incorrect item.

## Existing safeguards retained

Placement uses the existing atomic placement RPC, which records stock movement and line status together. Routing suggestions remain facility scoped and distinguish proposed bins from verified layout. Lot/expiry consolidation, capacity suggestions and manual full-bin exclusion are unchanged. Blind receiving remains separate from placement.

## Verification and limits

Regression tests cover invalid and duplicate counts, site mismatch, exact identifiers, decimal placement, completion failure after saved placement, and retrying short-placement completion. Existing mobile/process/routing/service tests are rerun with TypeScript and size checks. Full suite retains its pre-existing failures.

No database changes were made in this pass. Live capacity enforcement, multi-device placement races, general job-completion authorization, PO synchronization, and scanner hardware were not re-certified against staging. This pass does not claim that routing estimates are authoritative bin capacity. The existing database placement path remains unchanged.
